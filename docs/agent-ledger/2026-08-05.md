### The fix Codex specified, and a measurement gap it exposed

Codex proposed a **per-era nullable-grain contract** instead of a spec-level on/off switch:
`nullable_grain_columns` on `StreamEra` (and on `StreamSpec` for era-less streams), with the era's
value winning. Grain enforcement is now **ON** for both streams and nullability is declared per era:
FF `("player_id",)`, depth weekly `("week", "depth_position")`, depth daily `()`.

**`depth_position` is in that list because of a defect in my own measurement.** I declared only
`week` nullable after measuring `is_null()` counts — which returned zero for `depth_position`. The
contract test then failed on real fixture data. The reason: `depth_position` carries **`'\n    '`**,
a **whitespace scrape artifact**, not a null — **3,964 rows across 2018-2024**, and 467 in 2024
alone. A null-count measurement cannot see it. This is the same artifact class the injury stream
already normalizes, and the fix is the same: `blank_as_null_columns=("depth_position",)`, so the
store holds one spelling of nothing. Measured: with blanks normalized the weekly grain stays
**unique in every season**. Live store now holds **zero** literal-whitespace `depth_position` values.

*This is the same shape as the Super Bowl row: I measured the wrong thing, got a clean answer, and
believed it. Nulls are not blanks.*

### Boolean domain, corrected properly

The guard now checks the **raw value** against `{"0","1","True","False"}` — SQLite measurably stores
`'0'`/`'1'` and Python bools round-trip as `'True'`/`'False'`. Checking the *coerced integer* was the
error: `'01'` and `'+1'` both parse to 1. Deliberately NOT widening to `'true'`/`'yes'` — that would
be inventing a dialect we were never given. All of Codex's reproducers plus `'1.0'` and `' 1'` now
refuse with the Boolean-specific error; clean data publishes unchanged (96/96 True in the fixture).
